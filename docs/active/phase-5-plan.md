### C1a — shared synthetic runner interface

Create `verifyPublicPsx` in the proposed `scripts/lib/real-ghidra-psx-public.mjs` with this single named argument contract:

```ts
verifyPublicPsx({
  executable, // absolute executable; node for repository, installed rea for package
  prefixArgs, // readonly string[]; repository dispatcher path or [] for installed rea
  environment, // complete caller-prepared Record<string,string>, copied by helper
  workspace, // absolute existing private empty child directory owned by caller
  record, // async (event: PublicPsxEvent) => Promise<void>, durable capture before assertions
}): Promise<PublicPsxOutcome>
```

No optional lifecycle/stage switches: both source and installed-package callers execute the **same full** semantic, schema, snapshot, negative and cancellation matrix. No arbitrary binary argument is accepted: this helper creates only the original synthetic fixtures. Caller creates a distinct empty workspace child for each invocation and owns eventual removal; helper owns every file/subdirectory/session/transport/process it allocates inside it. Helper runs children with `cwd:workspace` so package acceptance cannot accidentally depend on repository cwd. Helper must settle its acquired resources before returning; caller must not remove workspace while returned ownership is unresolved.

Caller prepares environment from inherited string-valued entries plus explicit absolute Ghidra/JDK and run-local TMPDIR/HOME/config/cache overrides. Helper passes this copy to children without merging ambient `process.env` again. Inheritance supports installed Java/process tooling; it is not permission to persist the environment. Caller/report records only selected nonsecret GHIDRA_INSTALL_DIR, JAVA_HOME, run-local path overrides and actual executable/version/path-resolution facts; never the full inherited environment. Package caller removes repository-specific module-resolution overrides (including NODE_PATH/NODE_OPTIONS if set), places the pinned runtime plus necessary host tools on PATH, and records this isolation decision without persisting unrelated values. Credentials remain redacted per C3.

`PublicPsxEvent` is a discriminated JSON-serializable record with monotonic `sequence`, `stage`, `case_id`, `adapter` (`cli` or `mcp`, omitted only for common preflight/settlement), and `kind`: `invocation`, `raw_result`, `observation`, `assertion`, `failure`, or `settlement`. Invocation retains exact executable/argv/cwd and owned identity; raw_result retains complete output/reply and exit/transport status before parsing; observation retains parsed Evidence/profile; assertion names the criterion and outcome. The helper awaits `record(event)` before dependent parsing/assertion. The callback writes into the caller's ignored capture root outside the removable workspace; it must neither mutate the event nor suppress persistence errors. Credential redaction happens before calling it, with an explicit redaction marker. No capped diagnostic tail substitutes for complete-stream capture. An event-write failure is a capture failure, triggers settlement, and prevents success; retain the event in memory in the returned outcome for caller fallback recording.

`PublicPsxOutcome` contains `ok:boolean`, `cases:[{id,adapter,status:"passed"|"failed"|"inconclusive",evidence_sequences:number[]}]`, fixture source paths/digests, actual target/profile/run identities, owned runtime/root inventory, `failures:[{stage,case_id?,message,cause?}]`, `unpersisted_events`, and `settlement:{verified_empty_lineage:boolean,remaining_roots:string[],unresolved_owners:...[]}`. Every unresolved owner retains its exact close handle and an awaited retry method in memory, alongside a serializable identity description for the report; the caller does not serialize handles. `ok` requires every required case passed, no failures or unpersisted events, and fully verified settlement. After argument validation, execution/capture/assertion failures are returned in this outcome after settlement rather than thrown past the caller's report writer. Invalid arguments throw before allocation. The top-level source/package runner persists the final outcome, performs its independent asset/source/code checks and workspace cleanup, completes verifier lineage, writes the final report and sets nonzero exit on any failure. It cannot turn `ok:false` into acceptance after cleanup retries.

The helper may export small public adapter/transport utilities for P5-12 (supervised CLI invocation, named MCP Evidence call and owned session close), with the same durable event and ownership conventions. **The local game runner never calls `verifyPublicPsx`, `verifyPsxInstructionFlow` or the synthetic fixed oracle on game bytes.** It uses those lower-level adapters in its own explicitly enumerated bounded sequence and compares current header/source/observed entry facts. Package helper integration depends only on the named interface and outcomes above, not shared mutable report arrays or private implementation callbacks.
